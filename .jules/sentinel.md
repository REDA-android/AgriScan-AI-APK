## 2024-05-18 - Missing Input Validation combined with Large Global Payload Limit
**Vulnerability:** The application had a global JSON payload limit set very high (`app.use(express.json({ limit: "100mb" }));`) to accommodate image uploads for analysis. However, this large limit applied to all endpoints, including text-only endpoints like `/api/gemini/chat`, which lacked field-level length validation on the `message` input.
**Learning:** Setting a high global payload size limit creates a Denial of Service (DoS) vulnerability and risks API quota exhaustion if text inputs on specific endpoints are not explicitly restricted to a reasonable length. An attacker could send a 99MB text message to the chat endpoint, potentially crashing the Node.js process, exceeding downstream API limits, or causing massive latency.
**Prevention:** Always combine high global payload limits with strict, endpoint-specific input length validation. Apply defense-in-depth by enforcing constraints at the route handler level (e.g., `if (message.length > 5000) return res.status(400)`), even if the global server parser accepts larger bodies.
