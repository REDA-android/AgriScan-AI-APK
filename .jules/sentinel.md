## 2024-05-24 - [DOM XSS in Global Error Handlers]
**Vulnerability:** The application's global error handlers (`window.onerror` and `window.addEventListener('unhandledrejection')`) in `src/main.tsx` used `innerHTML` with string concatenation to display error details (messages, source paths, stack traces, and reasons) directly in a fixed overlay. This allowed DOM-based Cross-Site Scripting (XSS) if an error originated from unsanitized input (e.g., parsing a user-provided JSON payload or encountering an unexpected error related to manipulated query parameters).
**Learning:** Displaying diagnostic information on the screen using `innerHTML` is inherently risky, as error properties like `.message`, `.stack`, and `.reason` can easily contain untrusted data that gets executed when rendered as HTML.
**Prevention:** Always use safe DOM APIs like `document.createElement()`, `innerText`, and `appendChild()` instead of `innerHTML` when displaying untrusted data or error messages directly in the DOM.
