## 2024-05-24 - [Critical] Prevent DOM-based XSS in Global Error Handlers
**Vulnerability:** Found `innerHTML` being used directly with potentially unsanitized error messages (`message`, `source`, `event.reason`) in `window.onerror` and `unhandledrejection` handlers in `src/main.tsx`. If an attacker can trigger an error containing malicious script tags, this script will be executed.
**Learning:** Even benign-looking debugging features like global error overlays can introduce severe DOM-based XSS vulnerabilities if they use `innerHTML` to display dynamic data without sanitization. In a Single Page App context, this is a prime target since user input can often be coaxed into throwing errors.
**Prevention:** Always use safe DOM APIs like `document.createElement`, `textContent` or `innerText`, and `appendChild` when rendering dynamic strings to the DOM, especially in global/unrestricted scopes like error boundaries or top-level handlers. Avoid `innerHTML` entirely unless strictly necessary and combined with a robust sanitizer (like DOMPurify).
