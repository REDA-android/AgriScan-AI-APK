## 2024-05-18 - [Fix DOM XSS in Global Error Handlers]
**Vulnerability:** Global error handlers in `src/main.tsx` (`window.onerror` and `window.addEventListener('unhandledrejection')`) were dynamically constructing HTML using `.innerHTML` directly with error messages and stack traces. This exposed the application to DOM-based XSS if user-controlled input was present in the error context.
**Learning:** Client-side error logging and overlay mechanisms can inadvertently become XSS vectors if they directly interpolate un-sanitized values (even error messages) into the DOM via `.innerHTML`. This is especially relevant in single-page applications where errors might echo user inputs (e.g. failed API requests due to bad input).
**Prevention:** Always use safe DOM manipulation methods like `document.createElement()`, `Node.appendChild()`, and `.textContent` instead of `.innerHTML` when dynamically rendering error details or any content that might contain user-influenced data.
